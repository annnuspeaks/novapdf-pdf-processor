# P0.1.5 — Future Android Integration

**Decision:** Build the web app first, but keep processing logic behind reusable backend APIs where appropriate.

**Initial release:** Web only. No Android app development during the 2–3 day MVP.

**Future approach:** An Android client may call the same FastAPI endpoints for server-side operations. Suitable operations can later be added as on-device processing if practical.

**Design rules:**
- Keep business logic separate from UI components.
- Use documented request/response formats.
- Avoid browser-only assumptions inside backend services.
- Keep file handling and API errors predictable.

**Reason:** Shared APIs reduce duplicated implementation when an Android client is added.

**Acceptance criteria:**
- Core processing is not tightly coupled to React components.
- API endpoints and expected inputs/outputs are documented.
