# P0.4 — MVP Priority Decision

**Project:** Nexora PDF Tools  
**Status:** Locked for initial 2–3 day MVP  
**Decision date:** 2026-10-16

## P0.4.1 — Must-have tools

Limit the first release to five workflows:

1. **Images to PDF** — JPG/JPEG and PNG to one PDF.
2. **Merge PDFs** — combine PDFs in selected order.
3. **Split PDF** — split by page ranges; package multiple outputs as ZIP.
4. **Extract PDF Pages** — save selected pages as a new PDF. Share the same page-selection logic as Split where practical.
5. **Rotate PDF Pages** — rotate all pages or selected pages by 90-degree increments.
6. **Extract Text from PDF** — extract embedded/selectable text to TXT; clearly state that scanned PDFs require OCR and are not supported in MVP.

The five core tool cards are Images to PDF, Merge PDFs, Split / Extract Pages, Rotate PDF, and Extract Text. Split and Extract are combined into one MVP card to keep the interface small, but can use separate modes on the same page.

## P0.4.2 — Post-MVP

Defer these until the core workflows work end-to-end:
- PDF to Images (rendering dependency and memory cost)
- Word / Excel / PowerPoint to PDF (requires LibreOffice installed and working in the host runtime)
- Strong PDF compression / image recompression (quality and output-size trade-offs)
- Reorder Pages with visual drag-and-drop
- Delete Pages as a separate tool (can be added to the page-editing workflow later)
- Add Page Numbers and Watermark
- Extract Images from PDF (PDF image object edge cases)
- AI PDF Summarizer and Chat with PDF (local model size, speed, RAM, and licensing are unresolved)
- PDF Information Extractor (small optional enhancement if time remains)

## P0.4.3 — Hosting and runtime constraints

- **Frontend:** Vite/React is static-build friendly and can be hosted on a static host.
- **Backend:** PDF processing uses Python libraries and needs a Python-capable host that supports FastAPI/ASGI, dependency installation, temporary files, and adequate memory/time limits.
- **Serverless caution:** Short execution limits, request-body limits, ephemeral storage, and memory constraints can break large-file conversions. Test target limits before selecting a host.
- **LibreOffice:** Office conversion tools are not included in MVP because they need an installed system binary and can be difficult to support on constrained hosts.
- **PyMuPDF:** Not needed for the locked MVP. Its AGPL/commercial licensing terms require careful review before future use.
- **Temporary storage:** Use per-job temporary directories and clean files after processing. Never assume local storage is permanent.
- **Free hosting:** Free tiers can have sleeping services, low memory, build limits, or changing quotas. No particular provider or permanent free availability is guaranteed.
- **Upload limits:** Start with a conservative configurable limit (for example, 15 MB per file and a bounded page count); adjust only after testing the chosen host.
- **Security:** Validate file contents, use safe filenames, enforce timeouts/limits, and do not expose server paths or stack traces.

## Acceptance criteria

- [x] MVP tool list is limited and explicit.
- [x] Time-consuming tools are moved to post-MVP.
- [x] Hosting/runtime dependencies are recorded.
- [ ] Each selected tool passes valid, invalid, and edge-case tests before release.
